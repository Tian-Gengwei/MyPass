## 一、项目概述

### 1.1 项目定位
- **名称**: MyPass
- **类型**: 本地优先、跨平台、端到端加密的现代密码管理器
- **核心价值**: 安全、快速、跨平台统一体验
- **设计理念**: Vibe Coding - 聚焦高层意图，消除开发摩擦，实现极速迭代

### 1.2 核心技术栈
| 层次    | 技术选型                                            |
|-------|-------------------------------------------------|
| 核心逻辑  | Rust (`forbid(unsafe_code)`)                    |
| 应用壳   | Tauri 2.0                                       |
| 前端    | React + TailwindCSS + Shadcn/UI + Framer Motion |
| 状态管理  | Zustand                                         |
| 浏览器扩展 | WXT 框架                                          |
| 加密    | Argon2id + XChaCha20-Poly1305                   |

## 二、架构设计

### 2.1 底层存储模型

```
my_vault.vault/
├── vault.meta.json       # 库元数据（版本、KDF 参数、公开盐值）
├── master_key.enc        # 被主密码/生物识别密钥加密后的 MEK
├── manifest.enc          # 当前库的全局索引（加密 JSON）
├── objects/              # 条目与组的独立加密文件（按 Hash 切片）
│   ├── a1/b2/a1b2...enc  
│   └── d4/e5/d4e5...enc
└── logs/                 # 加密操作日志
```

**核心原则**:
- 库是一个目录，绝不是单文件
- 一条目一文件：`objects/` 目录下按 Hash 切片存储
- 局部更新：修改条目仅重写对应的几 KB `.enc` 文件

### 2.2 密码学设计

| 算法                 | 用途                    |
|--------------------|-----------------------|
| Argon2id           | 主密码 → KEK 密钥派生        |
| XChaCha20-Poly1305 | AEAD 认证加密，每条目独立 Nonce |
| ChaCha8            | 日志流加密                 |
| SHA-256            | 内容哈希、ID 生成            |

### 2.3 密钥层次

| 密钥       | 说明                               |
|----------|----------------------------------|
| MEK      | 主加密密钥，用于加密条目与 Manifest           |
| KEK      | 密钥加密密钥，由主密码派生，仅用于加密 MEK          |
| QuickKey | 256-bit 随机密钥，用于生物/PIN 秒解，存于系统密钥库 |
